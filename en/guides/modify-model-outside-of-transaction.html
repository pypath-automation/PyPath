"Attempt to modify the model outside of transaction": how to fix it

The error message everyone sees at some point. What it means, how to fix it in three lines, and the less obvious variants.

4 min read·Updated October 10, 2026·Checked against the Revit API 2025 documentation

On this page

  2. What it means
  3. The fix in three lines
  4. Variants you will run into
  5. One transaction at a time

Short answer: your script changes something in the model (for example with Set) without an open transaction. Put the change in a with revit.Transaction("name"): block, or start a Transaction yourself and finish it with Commit(). Reading is allowed without a transaction; changing never is.

The error message

In pyRevit the output window looks roughly like this. The exact layout differs per version and engine; the last line is always the same:

What it means

Revit wants every change to a model to happen inside a transaction: a defined step with a name. You can undo that step with Ctrl+Z, and if something goes wrong halfway, Revit rolls back the whole step. That keeps your model intact. Reading changes nothing and is allowed without a transaction; every change, even a single parameter, is not.

Without pyRevit, use Transaction(doc, "name") with Start(), Commit() and, on an error, RollBack(). A full example is in Read and set Revit parameters.

Variants you will run into

The change sits just outside the block

Python looks at indentation. If the line with Set is not indented under the with, the transaction is already closed when it runs:

A function that is called later

You write a helper function that sets a parameter and call it from somewhere without a transaction. The error then points at the line inside the function, not at the call. So agree on who opens the transaction: either the function itself, or always the code that calls it. In your own library "the caller" is usually handiest, so you can bundle several changes into one step.

A transaction on the wrong document

A transaction belongs to one document. If you work with several models at once, the transaction must be open on the document you are changing.

One transaction at a time

Only one transaction can be open per document. If you open another one with the pyRevit helper inside a revit.Transaction, it works within the first. For more complex cases the Revit API also has SubTransaction (a step within a transaction) and TransactionGroup (several transactions as one undo step). You rarely need those for ordinary buttons.
