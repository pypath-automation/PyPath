Read and set Revit parameters with Python (with a Transaction)

Parameters are the data of your model. How to read them, how to fill them in bulk, and the pitfalls that make Set do nothing or raise an error.

5 min read·Updated October 10, 2026·Checked against the Revit API 2025 documentation

On this page
  1. Getting a parameter
  2. Why LookupParameter breaks in a localised Revit
  3. Reading a value
  4. Changing a value: always in a Transaction
  5. Without pyRevit's helper: a plain Transaction
  6. Pitfalls

Short answer: get a parameter with element.get_Parameter(BuiltInParameter...) (or LookupParameter("name") for your own parameters), read it with AsString(), AsDouble(), AsInteger() or AsValueString(), and change it with Set(value). Changing is only allowed inside a Transaction; in pyRevit you write with revit.Transaction("name"):.

Getting a parameter

There are two ways:

  • get_Parameter(BuiltInParameter.X) for parameters Revit itself has, such as length, diameter, mark, comments or system name. The names are in the BuiltInParameter enum, for example CURVE_ELEM_LENGTH, RBS_PIPE_DIAMETER_PARAM, ALL_MODEL_MARK and ALL_MODEL_INSTANCE_COMMENTS.
  • LookupParameter("name") for parameters you added yourselves: project parameters and shared parameters.

Not sure what a parameter is called in the API? Select the element with the free RevitLookup add-in and look at its parameters.

Why LookupParameter breaks in a localised Revit

LookupParameter searches by the name you see in Revit. That depends on Revit's language: what is called "Length" in an English Revit is "Lengte" in a Dutch one. A script with LookupParameter("Length") then works for one colleague and not for another. So for built-in parameters always use get_Parameter with a BuiltInParameter: that name is the same in every language.

Reading a value

A parameter has a storage type (StorageType): text, decimal number, whole number or a reference to another element. The read function follows from it:

  • AsDouble() returns the number in Revit's internal unit: feet. 0.131 feet is 40 mm.
  • AsValueString() returns the text as Revit shows it, with the project units. Handy for a list, not for calculations.
  • AsString() is for text parameters, AsInteger() for whole numbers and yes/no, AsElementId() for references.

Pitfalls

Set returns False instead of raising an error

Pass a value of the wrong type and Set does nothing and returns False. A classic: a whole number on a parameter that stores decimals.

So check the result of Set, as in the comments example above.

Read-only parameters

Some parameters are calculated by Revit itself, such as the system name of a pipe. IsReadOnly is then True, and Set raises an error: The parameter is read-only. So check IsReadOnly first.

Type parameters

Part of the data is not on the element but on its type. You get the type with doc.GetElement(element.GetTypeId()). If you change a type parameter, it changes for all elements of that type. So do it on purpose.

Units

Lengths and diameters are stored in feet internally. Convert with UnitUtils.ConvertToInternalUnits and UnitUtils.ConvertFromInternalUnits, using for example UnitTypeId.Millimeters.

What exactly happens when you forget the transaction is covered in "Attempt to modify the model outside of transaction".
